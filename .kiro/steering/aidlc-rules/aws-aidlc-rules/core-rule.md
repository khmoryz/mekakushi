# 開発方針とタスク管理

## インクリメンタル開発の原則

### タスク分解の方針
- **段階的実装**: 一度に全機能を実装せず、基本機能から段階的に構築する
- **MVP優先**: 最小限の動作可能な機能を最初に実装し、その後機能を拡張する
- **小さな単位**: 各タスクは独立してテスト・検証可能な単位に分解する

### 実装サイクル
1. **実装**: 小さな機能単位で実装を完了
2. **ビルド**: 実装完了後、必ずビルドを実行して構文エラーを確認
3. **テスト**: 単体テストおよび統合テストを実行
4. **検証**: 期待通りの動作を確認
5. **コミット**: ビルドとテスト成功後にコミット

## 品質管理

### 必須チェックポイント
- **ビルド成功**: 各ステップ完了時にビルドエラーがないことを確認
- **テスト実行**: 関連するテストが全て通ることを確認
- **機能検証**: 実装した機能が要件通りに動作することを確認

### コミット規約
- ビルドとテストが成功した状態でのみコミット
- 各コミットは独立した機能単位を表す
- 適切なコミットメッセージを記述（commit-message-conventions.mdに従う）

## AI開発支援での適用

### コード生成時の指針
- 一度に大量のコードを生成せず、機能単位で段階的に生成
- 各生成ステップ後にビルド・テストを実行
- エラーが発生した場合は即座に修正してから次のステップに進む

### 品質保証
- 生成されたコードは必ず動作確認を行う
- テストコードも同時に生成し、機能の正確性を保証
- リファクタリングは動作確認後に実施
