# コミットメッセージ規約

## 基本フォーマット

```
<type>(<scope>): <subject>

<body>

<footer>
```

## Type（必須）
- **feat**: 新機能
- **fix**: バグ修正
- **docs**: ドキュメントのみの変更
- **style**: コードの意味に影響しない変更（空白、フォーマット、セミコロンの欠落など）
- **refactor**: バグ修正でも機能追加でもないコード変更
- **perf**: パフォーマンスを向上させるコード変更
- **test**: テストの追加や既存テストの修正
- **chore**: ビルドプロセスやツール、ライブラリの変更

## Scope（任意）
変更の影響範囲を示す：
- **api**: API関連
- **ui**: ユーザーインターフェース
- **auth**: 認証関連
- **db**: データベース関連
- **config**: 設定関連

## Subject（必須）
- 50文字以内
- 動詞の現在形を使用（「追加する」ではなく「追加」）
- 最初の文字は小文字
- 末尾にピリオドを付けない

## Body（任意）
- 72文字で改行
- 何を変更したかではなく、なぜ変更したかを説明
- 変更前の動作と変更後の動作を説明

## Footer（任意）
- Breaking Changes: `BREAKING CHANGE:` で始める
- Issue参照: `Closes #123`, `Fixes #456`

## 例

```
feat(auth): ユーザー認証機能を追加

OAuth2.0を使用したGoogle認証を実装。
セキュリティ要件を満たすため、JWTトークンによる
セッション管理も含む。

Closes #123
```

```
fix(api): ユーザー検索でnullポインタ例外を修正

検索条件が空の場合のハンドリングを追加。
エラーログの改善も含む。

Fixes #456
```

## ルール
1. **必須項目**: type と subject は必須
2. **文字数制限**: subject は50文字以内、body は72文字で改行
3. **言語**: 日本語または英語（プロジェクトで統一）
4. **現在形**: 動詞は現在形を使用
5. **明確性**: 変更内容が分かりやすいように記述

## 禁止事項
- 曖昧な表現（「修正」「更新」のみ）
- 複数の変更を1つのコミットにまとめる
- WIP（Work In Progress）コミットをmainブランチにマージ
