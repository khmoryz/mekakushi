# 作業単位定義

## ユニット概要

### ユニット名
**TextMaskingApp**

### ユニットタイプ
**統合デスクトップアプリケーション** - 単一のElectronアプリケーションとして実装

### 技術スタック
- **フロントエンド**: Electron + React/Vue + TypeScript
- **バックエンド**: Node.js + TypeScript
- **データ**: ローカルJSONファイル
- **ビルド**: Electron Builder

## ユニット責任

### 主要責任
1. **テキスト入力管理**
   - クリップボードからのテキスト取得
   - ユーザーによるテキスト入力・編集
   - テキスト選択とハイライト機能

2. **マスキング処理実行**
   - 手動選択によるマスキング
   - 正規表現パターンによる自動マスキング
   - 事前定義カテゴリ（メール、電話番号）の検出
   - 一貫性のあるマスキング（同じテキスト→同じマスク）

3. **辞書管理**
   - マスキング辞書の永続化
   - 辞書エントリの追加・編集・削除
   - 自動辞書更新
   - 辞書ベースマスキング

4. **ユーザーインターフェース**
   - デュアルパネルレイアウト（入力・出力）
   - マスキング制御パネル
   - 辞書管理インターフェース
   - エラー表示とフィードバック

5. **クリップボード統合**
   - システムクリップボードからの読み取り
   - マスキング結果のクリップボード書き込み
   - クリップボード操作のフィードバック

## ユニット境界

### 含まれる機能
- **すべてのコアマスキング機能**
- **完全なユーザーインターフェース**
- **ローカルデータ永続化**
- **システム統合（クリップボード）**

### 除外される機能
- **ネットワーク通信** - ローカル処理のみ
- **ファイルインポート/エクスポート** - 初期バージョンでは対象外
- **プラグインシステム** - シンプルさを重視
- **他アプリとのAPI統合** - 最小限の要件に焦点

### 外部依存関係
- **Electron Framework** - デスクトップアプリケーション基盤
- **Node.js Runtime** - バックエンド処理
- **macOS System APIs** - クリップボード、ファイルシステム
- **TypeScript Compiler** - 型安全性

## アーキテクチャ構成

### プロセス構成
```
TextMaskingApp
├── メインプロセス (Node.js + TypeScript)
│   ├── MaskingEngine - 統合マスキング処理
│   ├── Dictionary - 辞書データ管理
│   └── FileManager - ファイル操作
└── レンダラープロセス (Web + TypeScript)
    ├── App - アプリケーション状態管理
    ├── InputPanel - テキスト入力
    ├── OutputPanel - 結果表示
    ├── Controls - マスキング制御
    └── DictionaryPanel - 辞書管理
```

### データフロー
```
1. ユーザー入力 → InputPanel → App State
2. マスキング要求 → IPC → MaskingEngine
3. 処理結果 → IPC → App State → OutputPanel
4. 辞書操作 → IPC → Dictionary → FileManager
```

### 品質目標

## 成功基準

### 機能的成功基準
- ✅ クリップボード統合が正常に動作
- ✅ 手動・自動マスキングが期待通りに実行
- ✅ 辞書の永続化と再利用が機能

- ✅ エラー発生時に明確なフィードバックを提供

## 将来の拡張可能性

### 考慮済み拡張ポイント
- **設定システム**: ユーザー設定の永続化

このユニット定義は、シンプルで実用的なアプローチを採用し、ユーザーの要求に応じて最小限の技術スタックで最大の価値を提供することを目指しています。
